§0Executive summary

The pivot, and the calls it forces

The template inverts its delivery unit — from Vercel + Neon git push (a disposable prototype rail) to a dockerized Next.js app + dockerized Postgres as the fork-and-ship unit, production-grade from day one. Four operator decisions bind the research: deploy-per-tenant (no in-app row-level tenancy — ADR-011 kept), enterprise-only (the personal/shared tier split collapses into one enterprise floor), compose-now / k8s-ready, and self-hosted dockerized Postgres as the default (Neon an option). The unchanged constant is the Claude harness — the standard it enforces rises. Across five domains, 43 seed items were benchmarked against 4 lenses each (battle-tested / highest-star / enterprise-grade / best pure-OSS) and scored for fit against the fixed stack.

Ten load-bearing calls

  • Docker — Caddy + compose is the shape. Ship docker-compose.prod.yml (app + postgres:17/pgvector + Redis + Caddy auto-TLS proxy + object store), health-checked, compose secrets:; single-node Postgres is correct for deploy-per-tenant v1. HA (Patroni/CloudNativePG) is a k8s-later anti-pattern in compose.
  • AI runtime — BUILD, don't buy. The deferred "agent runtime" call resolves to a thin wrapper on the Anthropic SDK's native toolRunner() + betaZodTool — zero deps, zero lock-in — not a framework (Mastra/LangGraph = keep-as-option).
  • Vectors stay in the box. pgvector (HNSW) on the existing dockerized Postgres; pgvectorscale is the in-place upgrade past ~10M vectors. Pinecone rejected (managed SaaS breaks self-containment).
  • Identity — self-hosted bridge, not per-connection SaaS. Keep Auth.js; add an Ory Polis / BoxyHQ SAML→OIDC + SCIM bridge container (Auth.js ships the boxyhq-saml provider). WorkOS's ~$125/connection model is structurally wrong for one-org-per-deploy.
  • AuthZ — Cerbos sidecar. A stateless YAML-policy PDP wired into the existing with*Auth seam takes RBAC beyond the 3-role enum without exploding it.
  • Distributed rate limit is a correctness fix, not a nicety. The in-memory limiter gives an attacker N × limit across replicas. Swap internals to @upstash/ratelimit on the compose Redis, keep the withRateLimit API.
  • Observability — one pane. OTel via @vercel/otel (no next.config change) → SigNoz self-hosted for traces + metrics + logs; the OTLP endpoint is a config swap to Grafana Cloud / Datadog.
  • MinIO is no longer the default. catch MinIO community edition went maintenance-mode (Dec 2025) — build to the S3 API, default OSS backend = Garage v2; cloud S3 stays the option.
  • Supply chain — SHA-pin everything. catch the March 2026 Trivy supply-chain compromise (75 poisoned action tags) means every third-party GitHub Action pins by commit SHA and scanner images by digest. Trivy the tool is still the pick.
  • Governance — clone the model onto AI. The harness already is an app-factory (scaffold = golden path, ESLint/pillars = policy-as-code + fitness functions). The pivot duplicates spec → judge → gate → guardrail from code onto model outputs (new ai-eval agent + AI-eval gate + a 6th "AI-Quality" pillar).
Current-events catches that moved the defaults: MinIO CE maintenance-mode (Dec 2025) → Garage; pgBackRest 2026 maintenance scare (archived → "will continue" 2026-05-18) → WAL-G default; Trivy March-2026 supply-chain compromise → SHA-pin actions + digest-pin scanners; Inngest's orchestration engine cannot self-host → Trigger.dev; the agent runtime is a thin wrapper on Anthropic's native tool-runner, not a framework.

§1Docker-first delivery & infrastructure

Docker delivery & the self-hosted data plane

The pivot inverts the delivery unit to a dockerized Next.js app + dockerized Postgres, deploy-per-tenant, compose-now / k8s-ready. The good news: the repo already ships a correct multi-stage standalone Dockerfile (non-root, output:"standalone" gated behind DOCKER_BUILD=1, prisma migrate deploy at entrypoint). The pivot is mostly promoting existing scaffolding to default + adding the production compose topology + the operational data-plane layer (pooling, backup, object store, proxy) — not a from-scratch build. The single hard constraint: output:"standalone" stays env-gated so a Vercel fallback build is byte-identical (ADR-030 §1). Two "obvious" 2025–26 defaults moved: MinIO CE → maintenance-mode and pgBackRest → maintenance scare — both reshape the recommendation below.

§2AI & agent application stack (Axis 2)

The lib/ai/* layer the template has zero primitives for

This resolves the largest gap in the pivot: the repo is a CRUD/RBAC/audit template with no AI runtime (the claude-api skill is guidance, not shipped code). The headline call — the one operator decision explicitly deferred to research — is BUILD a thin wrapper on the Anthropic SDK's native tool-runner; do NOT adopt an agent framework for v1. Native client.beta.messages.toolRunner() gives a production agent loop (retries, streaming, AbortSignal cancellation, zod-typed tools) for zero extra deps and zero lock-in. Everything else stays inside the dockerized box: pgvector for vectors, Voyage for embeddings (Anthropic's own recommendation — it ships no first-party embedding endpoint), native SSE streaming, Promptfoo as the zero-infra eval gate (Langfuse later), and Trigger.dev over Inngest because Inngest's engine cannot be self-hosted.

§3Enterprise identity & data protection (Axis 3)

Raising the identity floor without breaking deploy-per-tenant

The floor must rise from "opt-in single-provider Entra ID (ADR-024)" to a real enterprise floor: multi-IdP SSO (SAML+OIDC) + SCIM + fine-grained authZ + field encryption + secrets management + tamper-evident audit. The decisive constraint is deploy-per-tenant + self-hosted: one deployment = one org = one connection, so per-connection SaaS pricing (WorkOS ~$125/SSO-connection/mo + $125 for SCIM) is structurally wrong here. The clean architecture keeps Auth.js v5 as the session/RBAC layer and adds a self-hostable SAML/OIDC + SCIM bridge container (Ory Polis / BoxyHQ Jackson) that Auth.js already ships a first-party boxyhq-saml provider for. Everything else is a Prisma-extension or sidecar pattern mirroring invariants the repo already owns.

§4Observability, supply chain & CI/CD

The enforcement & operations half of "production-grade from day one"

The founding premise — "free plan, CI dormant, /ship is the gate" — inverts. Enterprise means live CI/CD from day one: the dormant Actions workflows activate, and today's skip-if-absent gates (knip, jscpd, coverage, size-limit) plus the --full-only container scan and SBOM step become hard CI fails. The other structural change is the distributed floor: the in-memory lib/rate-limit.ts is silently wrong across replicas (an attacker gets N × limit), so a Redis-backed limiter is a v1 correctness requirement. A recurring 2026 lesson threads every verdict: the March 2026 Trivy supply-chain compromise (75 poisoned action tags) → pin every third-party Action by commit SHA, digest-pin scanner images.

§5Enterprise architects & AI-era patterns

The industry already built this — twice over

The harness is a single-repo, single-operator instance of the enterprise app-factory stack: /scaffold-entity is a golden-path software template, the ESLint rules + /ship gates are policy-as-code, and the five pillars are architecture fitness functions. It lacks only a catalog (multi-app inventory) and an externalized policy layer for the infra/config surface. Separately, the harness has independently reinvented most AI-era patterns — and for two (enforced spec-driven development via /blueprint, and LLM-as-judge via senior-code-reviewer) is arguably ahead of the named OSS tools because ours are enforced gates, not opt-in tooling. The pivot's payoff: don't invent a new governance model — clone the existing one onto the AI surface (spec → judge → gate → guardrail).

Part A — How enterprise orgs structure an "app factory"

The organizing discipline is platform engineering + golden paths (Spotify's "golden path", Netflix's "paved road"): make the supported, secure-by-default path the path of least resistance. Four building blocks recur — an IDP/service catalog (Backstage), scaffolding/generators (Nx, Plop, Yeoman, Cookiecutter), policy-as-code (OPA/Conftest), and architecture fitness functions (Building Evolutionary Architectures). Our template is precisely this thesis at repo scale.
