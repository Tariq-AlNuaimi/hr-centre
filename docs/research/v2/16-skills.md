# A.1 — Skills & Golden-Path Workflows (Enterprise Benchmark v2)

> Exhaustive 4-lens top-10 pass — **meta** about the harness itself, not npm libraries. The "candidates" are (a) skill/workflow-packaging approaches + golden-path generators in the ecosystem, and (b) the CATEGORIES of skills a best-in-class enterprise Claude harness should ship. Lens tags: **BT** battle-tested (proven pattern in prod orgs) · **HS** highest-star/most-popular · **ENT** enterprise-grade (SSO/compliance/commercial-backing/air-gap) · **OSS** best pure open-source. Stars/versions/licenses verified via web on **2026-07-11** (dated inline). Scored against the fixed stack in `METHODOLOGY.md`; honors the pivot (enterprise-only, deploy-per-tenant, Docker-first, Claude-first AI).

**What we ship today (28 skills + 4 agents).** Skills: `adr, ai-eval, audit, batch, blueprint, conform, cover, deploy, design-qa, design-system, docker, first-fork, handoff, handoff-session, manual-uat, migrate-from, new-project, qa, quickstart, rebrand, remember, scaffold-ai-endpoint, scaffold-entity, scale-up, ship, stack-advisor, sync-from-template, uat`. Agents (`.claude/agents/*`): `scout, senior-code-reviewer, security-architect, sre`. Packaging: one directory per skill, each a `SKILL.md` with YAML frontmatter (`name` + trigger-phrase `description`) + a Markdown body, several backed by a `scripts/*.mjs` generator. This is **exactly** the Anthropic Agent Skills format [1][3].

**The 2026 landscape in one paragraph.** Anthropic unified slash-commands and skills into a single **Agent Skills** primitive (Oct 2025), shipped the `anthropics/skills` reference library (160k★, Apache-2.0 + source-available doc skills) [3], and launched the Claude Code **plugin** marketplace (a plugin = bundled skills+agents+hooks+commands as a git repo) [1]. The community exploded: **Superpowers** (obra/superpowers, 252k★ MIT, v6.1.1) is now an official-marketplace "agentic skills framework + methodology" [2], and `awesome-claude-code` (49.8k★) catalogs the field [4]. In parallel, platform-engineering's **golden-path** tradition (Backstage software templates 33.8k★ [5], Cookiecutter 25k★ [6], Nx generators 29.2k★ [7]) is converging with agent skills — **Spotify's "golden state"** now feeds both human devs and their Claude-Agent-SDK background agent **Honk** (1,500+ merged PRs) through Backstage + a lint feedback loop [8], and **AWS shipped an Agent Toolkit** (May 2026) that packages "validated, up-to-date procedures" as agent skills [9]. Our harness is squarely on the right side of this convergence; the gaps are in _breadth of lifecycle coverage_, not format.

**Head-to-head.** We are on the _native, correct_ format — `anthropics/skills` (160k★) IS our packaging convention, so there is nothing to migrate to [3]. The real question is the **distribution layer**: today our 28 skills live loose under `.claude/skills/` with no plugin manifest, no version, and no marketplace entry, so a fork can't `plugin install` them or know it's stale (our `sync-from-template` compensates via path-scoped checkout, but that's a template-specific hack). Superpowers (252k★) shows the alternative — a versioned marketplace plugin usable across Cursor/Codex/Gemini — but its _methodology_ overlaps ours (brainstorm→spec→plan→TDD ≈ our `blueprint`→`ship`→`qa`), and adopting it wholesale would fork our opinionated gate model. Backstage templates and Cookiecutter are the _human_ golden-path world; the 2026 convergence (Spotify Honk [8], AWS toolkit [9]) is that the same golden path must now serve agents — which is exactly what our `SKILL.md` + `scripts/*.mjs` pairing does.

**Recommendation:** **KEEP+HARDEN.** Format is already best-in-class — do not change it. Harden the **distribution layer**: (a) add a `plugin.json` / marketplace manifest so the 28 skills become an installable, _versioned_ Claude Code plugin (a fork can pin + upgrade instead of `sync-from-template`'s path checkout); (b) publish it to a private/internal marketplace at `/handoff`; (c) adopt the `anthropics/skills` `template/` scaffold + `/spec` conventions verbatim so a fork author writes new skills the standard way; (d) cherry-pick Superpowers _techniques_ (its skills-lab patterns) without adopting its competing methodology. **Fit: 5/5.** **ADR impact:** new ADR "package the harness as a versioned Claude Code plugin (marketplace-distributable), superseding `sync-from-template` as the upgrade path."

### 2 — Golden-path scaffold generators

**One line:** Turn a declarative request into working, on-convention files/repos. Current: **`scaffold-entity`** (Prisma model + zod + routes + pages + nav + recycling-bin, via `scripts/scaffold-entity.mjs`), **`scaffold-ai-endpoint`**, **`new-project`** (repo+Neon+Vercel+DNS), **`deploy`**, **`rebrand`**, **`migrate-from`** — all bespoke Node generators, not a generic engine.

**Head-to-head.** Our bespoke `.mjs` generators are the _right_ call for the **security-invariant** part of scaffolding — `scaffold-entity` doesn't just stamp files, it registers the model for audit + soft-delete + recycling-bin + RBAC-gated routes and forces the `SCRUB_FIELDS` gate for Restricted columns, which no generic engine (Plop/Hygen/Cookiecutter) can encode. Where the generic tools win is **breadth and update-after-generate**: Nx's generator+**migration** model (codemods that upgrade already-generated code) and Copier's `update` command both solve the exact problem our `sync-from-template` wrestles with (a fork drifting from the template). Backstage is the enterprise _self-service portal_ layer — overkill for a single-repo template but the pattern to grow into if the harness ever serves many tenant repos from a catalog. The 2026 signal (Spotify Honk on Backstage + golden-state lint loop [8]; AWS agent-generators [9]) is that scaffold generators must emit code an _agent_ can then extend and that _lints itself back onto the golden path_ — which our ESLint rules + `/ship` gates already do.

**Recommendation:** **KEEP+HARDEN.** Keep the bespoke generators (they encode invariants a generic engine can't). Harden the two weak spots: (a) borrow **Copier's/Nx's update model** — give `scaffold-entity` and `sync-from-template` a _migration/codemod_ mode so template upgrades re-apply to generated forks instead of manual diffs; (b) add a thin **manifest** (what each generator produced + template version) so drift is detectable; (c) at multi-tenant scale, expose the generators behind a **Backstage-style catalog** entry (defer to post-v1 per pivot). Do **not** replace the `.mjs` scripts with Plop/Hygen — that would lose the security wiring. **Fit: 5/5.** **ADR impact:** ADR "scaffold generators gain an update/codemod mode (Nx/Copier-style); manifest-track generated artifacts."

Under the pivot — Docker-first, deploy-per-tenant, **IT operates production** — shipping code without a runbook is shipping a car with no manual. `/runbook` (pairing with the `sre` agent, emitting a gate-tracked `docs/runbooks/*.md` that `/handoff` bundles) closes the highest-severity hole and completes the agent/skill/artifact symmetry the rest of the harness already has.

## Current-events catches (flag)

- **Superpowers' meteoric star count is real but young.** 252k★ (Jul 2 2026, v6.1.1) [2] from an Oct-2025 launch — extraordinary velocity, MIT, in Anthropic's official marketplace. Treat as a _technique_ source, **not** a dependency to adopt: its brainstorm→spec→plan→TDD methodology _competes with_ our opinionated gate model, so importing it wholesale would fork our conventions. Cherry-pick, don't swap.
- **Slash-commands unified into skills (2025).** Anthropic merged `.claude/commands/` into Skills — our `SKILL.md`-only convention is already on the right side; forks carrying legacy `commands/` dirs should migrate [1].
- **`anthropics/skills` doc skills are source-available, not OSS.** `skills/{docx,pdf,pptx,xlsx}` are _not_ Apache-2.0 [3] — if the harness ever vendors those, it inherits a non-OSS license. Our skills are all first-party MIT; no exposure today, but note it before copying reference skills.
- **Spotify Honk / AWS Agent Toolkit (2026) reset the bar.** Golden paths now must serve _agents_ with in-loop lint feedback and cost/security guardrails [8][9]. Our ESLint-rules-as-gates + `/ship` already implement the feedback loop; the gap is operational/FinOps skills (§5), not the core pattern.
