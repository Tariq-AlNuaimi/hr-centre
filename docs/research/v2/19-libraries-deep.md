## 1. License audit (redistributed-template lens)

## 3. Supply-chain posture of the toolchain (hardening beyond C11)

C11 (`11-supplychain-security.md`) already benched the _scanners_ (gitleaks/trivy/npm-audit/SBOM/SAST/signing). This section assesses **whether we generate + verify** the artifacts, and gives a 4-lens **top-10 of hardening controls NOT already covered there** — the _install-time_ and _lockfile-integrity_ layer, which is the actual shape of the 2025 npm-worm attacks.

**Current posture (what we have):** SBOM via `@cyclonedx/cyclonedx-npm` (`npm run sbom`, on-demand, `--omit dev`) · gitleaks (hard gate) · `npm audit` High+ (hard gate) · trivy image+config (`--full`) · husky hooks · `package-lock.json` present (npm integrity hashes). **Gaps:** SBOM is generated but **not verified/diffed or published as a signed release artifact**; **no install-time behavioral scanning** (the layer that catches Shai-Hulud/chalk-style malicious versions — `npm audit` never will); **no digest-pinning** of deps or base images enforced; **no provenance verification** on install; **no min-release-age policy** (installs pick up a version the _hour_ it's published — exactly the 2h chalk/debug exposure window); **no license-allowlist gate.**

### Top-10 supply-chain hardening controls to ADD (4-lens; not in C11)

| #   | Control                                                                                | Lens       | Cost           | What it defends (2025-26 threat)                                                                                                                                                        | Verdict                                                                                     |
| --- | -------------------------------------------------------------------------------------- | ---------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | **Socket** (install-time behavioral SCA)                                               | ENT·HS     | free tier/paid | Flags install scripts, network/fs access, obfuscation, typosquats, sudden maintainer-behavior change — **catches malicious versions `npm audit` can't** (Shai-Hulud/chalk class) [4][5] | **ADOPT — P0.** PR gate (warn, block on confirmed-malicious). The single highest-value add. |
| 2   | **Minimum-release-age policy** (pnpm `minimumReleaseAge`, or Socket/Renovate cooldown) | OSS·ENT    | free           | Won't install a version <3–7 days old → the 2h chalk/debug + worm windows expire before you ingest them [5]                                                                             | **ADOPT — P0.** Cheapest, highest-leverage single policy. Pair with Renovate cooldown.      |
| 3   | **`osv-scanner` (Google)**                                                             | BT·OSS     | free           | Lockfile CVE scan → **SARIF** into code-scanning; broader DB than npm-audit; better CI artifact                                                                                         | **ADOPT — P1.** Second CVE source (diversify from GHAdvisory-only).                         |
| 4   | **Renovate** (update automation w/ cooldown + grouping)                                | BT·HS·OSS  | free app       | Scheduled, grouped, min-age-gated dep PRs → ADR-017 "in-range continuously" without hand-bumping                                                                                        | **ADOPT — P1** (over Dependabot: configurable + self-host + cooldown).                      |
| 5   | **StepSecurity Harden-Runner**                                                         | ENT·HS     | free OSS tier  | Egress-filters the CI runner → a compromised build step **can't exfiltrate** secrets (the Trivy/tj-actions payload goal)                                                                | **ADOPT — P1.** Directly caps blast radius of a poisoned action/dep.                        |
| 6   | **Action SHA-pinning + `zizmor`/`pinact`**                                             | BT·OSS     | free           | Every 3rd-party action pinned to 40-char SHA; zizmor fails the build on a mutable `@v` ref (tj-actions class)                                                                           | **ADOPT — P0** (already flagged P0 in C11; restated — it's the same root cause as Trivy).   |
| 7   | **cosign (keyless) + SLSA provenance** on the release image                            | BT·OSS·ENT | free           | Signs the Docker delivery artifact; **verify-on-deploy** rejects an unsigned/tampered image (would've caught poisoned Trivy binaries)                                                   | **ADOPT — P1** (C11 §signing; Docker-first makes this concrete).                            |
| 8   | **License-allowlist gate** (`license-checker-rseidelsohn` / Syft+policy in CI)         | OSS        | free           | Fails the build if any dep resolves to AGPL/SSPL/BUSL/GPL-only → protects the _redistributed template_ invariant (§1)                                                                   | **ADOPT — P1.** Cheap insurance the fork lifecycle needs.                                   |
| 9   | **Lockfile-integrity + `npm ci --ignore-scripts` in CI/Docker**                        | BT·OSS     | free           | `npm ci` enforces lockfile hashes; `--ignore-scripts` blocks arbitrary install-time code (the worm's entry point) — allowlist scripts you truly need                                    | **ADOPT — P1.** Config-only; large payoff.                                                  |
| 10  | **Dependency-Track** (ingest the CycloneDX SBOM → continuous VEX)                      | ENT·OSS    | self-host      | Turns the one-shot SBOM into a _monitored_ inventory: alerts when a _new_ CVE hits a version already shipped                                                                            | **ADD-AS-OPTION — P2** (enterprise; pairs with §3 SBOM publish).                            |

**Head-to-head (the two that matter most):** the 2025 worm era proved that **CVE scanning is the wrong primary control for malicious packages** — a freshly-trojanized `chalk` has no CVE for hours. The two controls that actually blunt it are **behavioral install-time scanning (Socket, #1)** and a **minimum-release-age cooldown (#2)** — the latter is nearly free and single-handedly closes the "ingest the malicious version within its short exposure window" attack. Everything else (SARIF, Renovate, Harden-Runner, cosign) is defense-in-depth. **Recommended bundle: Socket + min-release-age + `npm ci --ignore-scripts` as the P0 install-time triad**, layered under the existing gitleaks/npm-audit/trivy gates.

**On SBOM:** we _generate_ CycloneDX but don't _use_ it. Upgrade to: (a) also SBOM the **Docker image** with Syft (C11's rec), (b) **publish both as signed release artifacts** (cosign-attest), (c) feed Dependency-Track for continuous VEX. An SBOM you don't diff or monitor is compliance theater.
