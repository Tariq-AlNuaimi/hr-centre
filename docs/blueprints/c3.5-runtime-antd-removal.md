# Blueprint — C3.5: migrate the remaining runtime-AntD surface onto the C2 primitives

**Status:** signed-off pending operator approval (plan mode) · **Tier:** shared
(template) · **Ask-before:** YES (app chrome + auth screens + a new-dep decision)
· **Program:** replatform-and-adoption (ADR-029) · **Blocks:** C4.

## was → now (the delta)

- **was:** C1 (Tailwind `@theme`) + C2 (shadcn/Radix primitive layer) + C3 (screen
  migration; design-qa axe-clean in light) have landed, BUT **19 files still import
  `antd`/`@ant-design/*` at RUNTIME** — all of `components/layout/*` (the app
  chrome), the auth screens, `settings/profile`, `UserForm`, and `KanbanBoard.impl`.
  That runtime-AntD is C4's hard prerequisite: you cannot drop the `antd` deps, the
  CSP `'unsafe-inline'` style exception, or the `no-raw-hex` AntD exemption while the
  chrome still renders AntD.
- **now:** every runtime `antd`/`@ant-design/*` import is gone from `app/**` and
  `components/**` (except the _type-only_ `ColumnsType`/`TableProps`/`PopconfirmProps`
  bridges + `antd-theme.ts`, which C4 removes). The app renders identically on
  shadcn/Radix + Tailwind tokens. `AntdRegistry` + `ConfigProvider` + `App` are
  removed from the provider chain. Re-run the design-qa axe bridge → still clean.

## Why (problem statement)

D3 ("replace AntD with Tailwind fully") is `[~]`. The chrome IS AntD (`Layout`,
`Menu`, `Dropdown`, `Avatar`, `ConfigProvider`, `AntdRegistry`, the `App` message
API, `theme.useToken()`). Until it moves onto the primitives built in C2, C4 is
blocked and the "fully replaced" bar is unmet. This is the real remainder the
session-4/5 handoffs mislabeled as done.

## User stories (this is a refactor — parity IS the acceptance criterion)

- **US-1 (operator/stakeholder):** As a user of any migrated screen, the app looks
  and behaves _identically_ after the migration — same layout, chrome, dark/light
  toggle, RTL, ⌘K palette, notifications bell, org switcher, user menu, breadcrumbs,
  auth split-screen, profile, user CRUD form, kanban. No visual or functional
  regression.
- **US-2 (operator):** As the person toggling theme, the dark/light/system toggle +
  cookie persistence + no-FOUC pre-hydration script keep working with no AntD
  `ConfigProvider`.
- **US-3 (developer):** As the next dev, toast/notify still works via the same
  `useNotify()` API (success/error/info/warning) — call sites are untouched; only the
  implementation swaps AntD `App.message` → sonner.
- **US-4 (fork author):** As someone running `/scaffold-entity`, the sidebar patch
  still inserts a new nav item correctly (the generator is updated in lockstep with
  the migrated sidebar's icon import + item shape).

### EARS acceptance criteria

- WHEN the app renders any dashboard page, the shell SHALL show header + sidebar +
  content + footer with the same spacing/elevation, with NO `antd` runtime import.
- WHEN the user presses ⌘K / Ctrl+K OR clicks the header search, the command palette
  SHALL open, filter, arrow-navigate, Enter-run, and Esc-close exactly as today.
- WHEN a react-query read fails with a `meta.errorMessage`, an error toast SHALL fire
  (the QueryProvider error bridge keeps working over sonner).
- WHEN `/ship` runs, typecheck + lint + tests + build + axe regression spec SHALL be
  green, and `grep -rE "from ['\"]antd['\"]|@ant-design/(icons|nextjs-registry)"` over
  `app/**` + `components/**` SHALL return ONLY type-only imports + `antd-theme.ts`.

## Happy path

Build the missing primitives → rewrite `use-notify` over sonner + mount `<Toaster>` →
swap 16 icons to lucide-react → migrate the 9 chrome components → migrate the 4 auth
screens → migrate profile + UserForm + KanbanBoard → strip `AntdRegistry`/
`ConfigProvider`/`App` from the provider chain → update globals.css layout rules →
update `scaffold-entity.mjs` in lockstep → `/ship` green → deploy → re-axe via bridge.

## Worst path (the risks + mitigations)

- **Theme flash / dark desync.** ThemeProvider's `useTheme()` context + the
  pre-hydration `THEME_INIT_SCRIPT` + `data-theme` on `<html>` already drive the
  Tailwind CSS-var swap independently of AntD. Mitigation: KEEP all of that; only
  remove `ConfigProvider`/`App`. Verify dark toggle + reload has no flash.
- **Toast provider ordering.** Today QueryProvider must sit inside AntD's `App`
  (`useNotify` reads `App.useApp()`). sonner's `toast()` is context-free (just mount
  `<Toaster/>` once), so the ordering constraint _relaxes_ — but keep the
  `QueryErrorBridge` structure so the bridge contract is unchanged.
- **Command palette regression.** It's already fully custom keyboard-driven; only the
  AntD `Modal`/`Input`/`Empty` shells + `theme.useToken()` inline styles change. Reuse
  the existing Radix `Dialog` (components/ui/dialog.tsx) + shadcn `Input` + a plain
  empty state. Preserve every keyboard handler + the `OPEN_COMMAND_PALETTE` event +
  `destroyOnHidden` semantics (Dialog unmounts on close).
- **Scaffold drift.** `scripts/scaffold-entity.mjs::patchSidebar()` matches
  `@ant-design/icons` import + the `icon: <AppstoreOutlined />` item shape. Migrating
  the sidebar BREAKS the generator silently. Mitigation: update `patchSidebar()` in the
  SAME change to match the lucide import (`LayoutGrid`) + the new item shape; the
  scaffold contract test (if any) stays green.
- **globals.css dead rules.** `.ant-layout-content { padding: var(--density-page) }`
  supplies page padding; `.ant-layout-header` supplies the sticky shadow;
  `.header-search-kbd` reads `--ant-color-*` cssVars. Migrating the shell orphans
  these. Mitigation: move page padding onto the migrated `Content` (Tailwind
  `p-density-page`), the header shadow onto the migrated header, and repoint the kbd
  vars to `var(--border)` / `var(--muted-foreground)`. Remove the `.ant-*` rules.
- **CSP.** DO NOT touch `middleware.ts` here. Dropping the style-src `'unsafe-inline'`
  is C4 — it stays permissive (harmless) until AntD's deps + registry are fully gone.
  Removing `AntdRegistry` from the tree is fine (no CSP change needed); the exception
  just goes unused until C4 removes it.
- **New deps.** See "Dependencies" — all shadcn-standard, each well under the 50 KB
  Ask-before ceiling, sanctioned under ADR-029's primitive-layer mandate. Surfaced
  for explicit approval anyway.

## Architecture sketch

### New primitives (components/ui/)

- `dropdown-menu.tsx` — Radix `@radix-ui/react-dropdown-menu` (AppHeader user menu,
  OrgSwitcher). shadcn API.
- `avatar.tsx` — Radix `@radix-ui/react-avatar` (AppHeader). Image + fallback.
- `sonner.tsx` (Toaster) — sonner `<Toaster/>`, theme-aware via `useTheme().isDark`,
  `richColors`, RTL-safe. Mounted once in the provider chain.
- `separator.tsx` — plain Tailwind `<div role="separator">` (Divider). NO new dep.
- `command-palette` — NOT a new dep; reuse `dialog.tsx` + `input.tsx` + custom list.

### Toast seam

- `hooks/use-notify.ts` → wrap sonner `toast.success/error/info/warning`. Same return
  shape `{ success, error, info, warning, notify }`. `notify` (rich AntD notification)
  maps to `toast(...)` with a description; call sites only use the four string helpers.

### Icon swap (16 → lucide-react)

Home, User→User, Settings, Trash2, ClipboardCheck (Audit), LogOut, Search,
ChevronDown, Check, Sun, Moon, Globe, Bell, Lightbulb (Bulb), Wrench (Tool),
(Windows→a Microsoft-style mark; use lucide's `Grid2x2`-free approach — render an
inline SVG or lucide `SquareStack`; DECISION: keep the Microsoft square-logo as a
tiny inline SVG so the SSO button stays recognizable). Scaffold's `AppstoreOutlined`
→ lucide `LayoutGrid`.

### Provider chain (app/[locale]/layout.tsx)

`<AntdRegistry><ThemeProvider><QueryProvider>` → `<ThemeProvider><QueryProvider>` +
mount `<Toaster/>` inside ThemeProvider (so it reads `useTheme`). Keep the nonce,
the pre-hydration script, next/font, NextIntl, SpeedInsights.

### Token mapping (AntD `theme.useToken()` → Tailwind classes)

`colorBorderSecondary`→`border-border`, `colorText`→`text-foreground`,
`colorTextSecondary/Tertiary`→`text-muted-foreground`, `colorBgContainer`→`bg-card`,
`colorBgElevated`→`bg-popover` (NEW token, below), `controlItemBgHover`/`rowHover`→
`hover:bg-accent` (NEW token), `colorPrimary`→`bg-primary`/`text-primary`,
`colorTextLightSolid`→`text-primary-foreground`, spacing tokens→`p-*`/`gap-*` on the
4px scale, `borderRadius`→`rounded-md`.

### New semantic tokens (app/tokens.css + globals.css dark overrides)

Add `--accent` / `--accent-foreground` (hover surface; light `#f6f7f9` per AntD
rowHover, dark `#1f242c`), `--popover` / `--popover-foreground` (elevated overlay;
light `#ffffff`, dark `#1d2129` per AntD colorBgElevated). Expose in the `@theme`
block as `--color-accent-surface`/`--color-popover`. **Note:** `--color-accent`
already = brand accent, so the hover token is named `--accent`/`bg-accent` distinctly
— confirm no class collision (brand accent utility is `text-accent`/`bg-accent`
currently pointing at `--color-accent`). To avoid collision, name the hover token
`--muted`-adjacent: **DECISION — reuse `hover:bg-muted` for hover surfaces** (already
exists, on-scale, avoids a token collision) and add ONLY `--popover`/`--popover-
foreground` for the elevated overlay surface. Sidebar active item uses a dark-safe
indigo: light `text-primary` (#4f46e5), dark needs the lighter `#a5b4fc` — add
`--nav-active-foreground` (light `var(--brand-primary)`, dark `#a5b4fc`) so the
migrated sidebar is dark-correct by construction. (Workstream D finishes the rest of
the dark audit; this just keeps C3.5 from _introducing_ a dark regression.)

### Layout primitives (AntD Layout/Sider/Header/Content/Footer → Tailwind)

- `AppShell` — `<div className="flex min-h-screen flex-col">` header on top, then a
  `<div className="flex flex-1">` sidebar + `<main>`.
- `AppSidebar` — `<aside>` with a collapse toggle (keep the `collapsible` +
  `breakpoint=lg` behavior: `useState` + a responsive hidden-below-lg default). Nav =
  a `<nav>` of `<button>`/`<Link>` items (NOT Radix — it's vertical nav, plain
  Tailwind + the `--nav-active-foreground` token). Preserve the scaffold marker
  comment + item shape.
- `AppHeader` — `<header className="sticky top-0 ...">`, DropdownMenu user menu,
  Avatar, the search-trigger button (keep `.header-search-*` classes), theme toggle,
  locale switch, NotificationsMenu, OrgSwitcher.
- `AppFooter` — `<footer>` centered muted text.
- `Content` — `<main className="min-h-[360px] p-density-page">` (moves the padding off
  `.ant-layout-content`).
