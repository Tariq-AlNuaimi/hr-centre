## 14. Solution architecture

**Objective:** system design, ADRs, architect agents, design docs.

The template already runs a **mature, native ADR practice** — 28 accepted records in `docs/decisions/`, an `/adr` skill that enforces numbering/status/supersession against a committed `ADR-TEMPLATE.md`, `/blueprint` for the architecture-sketch-plus-user-stories half of a plan, and a `Plan` agent plus `EnterPlanMode` auto-planning for high-blast-radius work — with every Ask-before change gated on a superseding ADR. So the *decision-record discipline* these repos exist to bootstrap is something we already have wired into the build loop, not a doc convention bolted on. Where the field genuinely leads us is in two orthogonal places: a **richer ADR schema** (MADR's explicit options/consequences-per-option, log4brains' browsable timeline UI) and **diagrams-as-code** (C4/Structurizr), neither of which our prose-ADR + Plan-agent stack produces today.
