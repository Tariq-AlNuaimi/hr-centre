# 04. Hooks

**Objective:** lifecycle event hooks for enforcement and observability.

**Synthesis.** The ecosystem splits cleanly into three camps: broad *educational showcases* that wire every event (both disler repos — mastery covers 13 event files; observability streams them to a live dashboard), *focused enforcement gates* that block on one or two events (webdevtodayjason's 17-hook suite, bartolli's TS/lint gate, karanb192's dangerous-command blocker, lasso's prompt-injection scanner), and *novelty/UX* toys (shanraisshan's sound-per-hook, gugug168's Chinese tooltips). Our 5 hooks are none of those: they are a *purpose-built durability + cost + token-thrift* set tuned to one operational reality — an ephemeral remote container that clones only what was pushed — so `session-stop.mjs` (hard-block on unpushed commits), `context-watchdog.mjs`, `session-receipt.mjs`, and `session-start.sh` solve problems none of these repos target. Where we are genuinely behind is *event breadth* and *output-side security*: we ship no PreToolUse/PostToolUse enforcement beyond `verbose-guard`, no secret-scan-on-tool-output, and no prompt-injection defense — all of which `/ship` (gitleaks) and ESLint cover at push time, not at tool time.
