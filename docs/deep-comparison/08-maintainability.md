# 08. Maintainability

_Objective: keep code maintainable, refactor continuously, cut tech debt. Snapshot 2026-07-02._

**This template's maintainability surface (what "WE have" means below):** Pillar #3 (Maintainable) is a `/ship`/`/qa` **gate** — reuse existing primitives (check `docs/REPO-MAP.md` before writing new), typed, no dead code, small forward-compatible migrations. It's supported by the `/simplify` skill (reuse/efficiency/altitude cleanups, applied), the native `/code-review` diff gate + async `senior-code-reviewer` breadth pass, `/conform` (bring foreign code to standard), and 10 local ESLint rules at `error` enforcing conventions (naming, layering `UI→API→service→Prisma`, no dead patterns). The stack is deliberately single-language (Next.js/TS/Prisma), so maintainability comes from a **narrow surface + mandatory review**, not from multi-language scoring or automated debt metrics.

## Synthesis

The field splits cleanly into two things this template does _not_ ship: (a) **automated debt/duplication/dead-code metrics** (Sonar, knip, jscpd) that put a measured number on maintainability and gate on it, and (b) **more/broader refactoring subagents** (wshobson, VoltAgent, dl-ezo) that overlap heavily with `/simplify` + `senior-code-reviewer` but add depth (legacy modernization, language breadth). The template genuinely wins on _enforcement wiring_ — its review passes are mandatory gates, not optional invocations, and its ESLint rules encode this codebase's real invariants (audit, auth layering) that no generic tool knows. But it has a real, honest gap: it asserts "no dead code" and "no duplication" as review-time _judgement_ with **zero automated detector** behind them, where knip and jscpd (both TS-native, both now shipping Claude skills/MCP) would give a cheap, deterministic gate. Ruff/Biome are wrong-language or redundant to the existing ESLint; SonarQube is too heavyweight for a solo prototype rail; the subagent collections are mostly already covered.
