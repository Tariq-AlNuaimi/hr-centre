## 11. Speed of development

_Objective: accelerate building — scaffold / generate / prototype / idea-to-app. This is the template's core value prop, so this is where it should compete hardest. Snapshot: 2026-07-02._

**Synthesis.** Speed-of-dev tooling splits into three shapes: **one-shot generators** that hand you a starting point and then go quiet (`create-t3-app`, `gpt-engineer`, `open-saas`), **prompt-to-app agents** that build a fresh app per session with no lasting structure (`bolt.new`, and `claude-code`/`gpt-engineer` in the general case), and **ongoing generator frameworks** that keep scaffolding new pieces across a project's life (`nx`, `wasp`). This template is the rare thing that combines all three registers: an ongoing entity generator (`/scaffold-entity` — Prisma model + zod + API routes + dashboard pages + sidebar nav + recycling-bin in one command), one-shot provisioning (`/new-project`/`/deploy` → GitHub + Neon + Vercel in ~3 min), and an idea-to-URL agent flow (`/quickstart`, ~10 min) — all riding an opinionated, security-gated Next.js/Prisma/Auth.js/AntD stack. Its two genuine peers here are **wasp** (declarative CRUD + one-command deploy, but you learn a bespoke DSL) and **open-saas** (more batteries out of the box — Stripe/S3/admin — but a static boilerplate with no per-entity generator of its own). Where the field ships either a generator OR a deploy OR a stack, this template ships the whole loop wired into one harness — and none of the ten repos pair scaffolding with a security/quality gate the way `/scaffold-entity` emits code that already satisfies the auth-wrapper/zod/audit/soft-delete invariants.
