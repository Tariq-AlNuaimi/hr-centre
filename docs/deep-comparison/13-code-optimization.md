# 13. Code optimization

**Objective:** refactor / simplify / clean code, remove dead code, improve efficiency.

**This template's surface:** `/simplify` (native skill — reuse/efficiency/altitude cleanups, quality-only, applies fixes), `/code-review` (native diff-scoped review that catches reuse/simplification/efficiency findings and can `--fix`), `/batch` (capped headless per-file codemod-style runs with a typecheck gate), and the **"no dead code" Maintainable pillar** enforced at review + `/ship`. No standalone dead-code scanner, duplication detector, or AST-rewrite engine is wired.

## Synthesis

For a single-stack (Next.js/TS/Prisma) prototype rail, the template's LLM-driven `/simplify` + `/code-review` loop covers the *judgment* half of code optimization well — reuse, altitude, honest simplification — and `/batch` gives it a real mechanical-transform lane. What it lacks is the **deterministic** half of this category: it has no dead-code/unused-export scanner (knip), no duplication detector (jscpd), and no AST structural-rewrite engine (ast-grep/codemod), all of which the field ships as CLIs *with MCP servers* that Claude Code can drive directly. The pure prompt-persona repos (everything-claude-code, wshobson, VoltAgent) are the template's direct peers and it broadly matches or beats them; the deterministic engines are where a fork would genuinely gain, since "no dead code" as a review-time pillar catches obvious cases but can't prove an export is unreferenced across the tree the way knip can.
