# 20. Planning

**Objective:** implementation planning, task decomposition, roadmapping, planner agents.

**Synthesis.** This template's planning is two deliberately *lightweight* halves: an **ephemeral approval gate** (`EnterPlanMode` — a plan you sign off on, then it evaporates; the `Plan` architect agent *returns* a step-by-step plan but doesn't persist it) plus a **persistent requirements contract** (`/blueprint` → committed `docs/blueprints/<feature>.md` with user stories, happy/worst scenarios, an architecture sketch, and the tier). What it structurally lacks — and what nearly every repo in this field has — is a **durable, dependency-ordered, resumable task decomposition** that survives the ephemeral remote containers CLAUDE.md itself warns about (`claude-task-master`'s `tasks.json`, `spec-kit`'s `tasks.md` with `[P]` markers, `cc-sdd`'s `_Depends:_` annotations, `Backlog.md`'s git kanban). For a disposable solo prototype rail that omission is by design, and the sanctioned fix is already named in CLAUDE.md: defer real multi-file features to **Superpowers `writing-plans`** (the lightest add), with **`claude-task-master`** as the structured growth-path option if forks outgrow a single session.
