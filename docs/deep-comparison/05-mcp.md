# 05. MCP servers

**Objective:** expose tools/data to agents via the Model Context Protocol.

**Synthesis.** This template is a **consumer of MCP, not a provider** — the right lens for this whole category. Its environment already wires four MCP servers (github-mcp-server, playwright-mcp, Figma, Replit) and its skills drive them: `/uat` `/design-qa` `/manual-uat` drive **playwright-mcp**, GitHub ops go through **github-mcp-server**. So "who wins for this objective" is almost always the repo — they _are_ the servers we'd consume — and the honest question is not compete-vs-lose but **wire-it-or-not**. Two of the ten (playwright-mcp #6, github-mcp-server #7) are already load-bearing here; the rest split into "adopt as a dev-loop server" (context7, chrome-devtools-mcp), "build-our-own tool" (fastmcp, if we ever expose the `/api/v1` seam per ADR-013), and "not relevant to an internal-tool factory" (blender, scrapegraph, mindsdb, the directory/reference lists).
