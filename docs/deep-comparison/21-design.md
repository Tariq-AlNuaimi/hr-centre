## 21. Design

The template's design system is a **prevent-then-audit code discipline** (`/design-system` builds on-token, `/design-qa` audits), anchored to a real token layer (`app/tokens.css` + `antd-theme.ts`) enforced by the `no-raw-hex-color` ESLint rule — the same tokens philosophy these repos preach, but wired into the CI gate rather than a designer's tool. Where we are genuinely thin is the **design-authoring / design-to-code seam**: none of our stack turns a Figma file (or a prompt) into a first-pass screen, and our token *pipeline* is hand-maintained rather than compiled from a source of truth. The 10 repos split cleanly into design tools (Penpot, superdesign), Figma↔code MCP bridges (Figma-Context-MCP, the three console/talk MCPs), token pipelines (style-dictionary, tokens-studio, gregorymm), and Claude-native design skills (design-mastery, claude2figma) — and the last two are our closest cousins, doing for Figma exactly what we do for AntD.

**Top thing to adopt:** A `/design-system` design-to-code sub-recipe that ingests a Figma frame via the available Figma MCP (Framelink/southleft-style) and re-expresses it on our shared primitives + tokens — the one seam we're genuinely missing; secondarily, a single `tokens.json` DTCG source compiled by style-dictionary to kill the `tokens.css` ↔ `antd-theme.ts` hand-sync drift.
