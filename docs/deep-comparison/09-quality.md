# 09. Quality — tit-for-tat vs. this template

**Objective:** overall code quality & quality gates.

**This template's quality stack:** `/qa` orchestrator (three gated tiers — design →
functional → UAT, per `.claude/skills/qa/SKILL.md`), `/ship` (typecheck / lint / tests /
build / secret-scan, stops on first failure), the native `/code-review` (pre-push,
diff-scoped gate), the `senior-code-reviewer` agent (post-push whole-change breadth pass),
**10 local ESLint rules at `error`**, and `docs/uat-rubric.md` as the written bar anchored
to the Five Pillars.

**Synthesis.** For the specific objective of _overall code quality and quality gates on
one owned application_, this template is unusually complete: it fuses deterministic linting
(ESLint + 10 project-specific rules), an AI diff review, an AI breadth review, and a
three-tier orchestrated QA pipeline into **mandatory gates** rather than optional tools —
the thing almost every repo below is a _component_ of. The genuine peers are the deterministic
linters (ESLint / Biome / Ruff — which we _use_ or whose niche is another language) and the
AI-review layers (`anthropics/claude-code` `/code-review`, `Storybloq/lenses`, `logic-lens`),
each of which does one slice deeper or broader than we do. Only **SonarQube** offers something
we structurally lack: quantified, trend-tracked quality _metrics and scoring_ (coverage %,
duplication %, maintainability ratings) as a hard numeric gate — our gates are pass/fail and
review-judgment, not scored.

## Top thing to adopt

Add quantified quality metrics to `/ship` (coverage threshold + duplication/complexity check, SonarQube-style) — the one axis where we have no gate at all — and restructure `senior-code-reviewer` into named blocking lenses (Storybloq) using logic-lens's execution-trace method.
