## How to use it

- Append a one-line, **dated** entry to the right section (newest at top of each
  section). Use `/remember "<entry>"` (it appends to the section AND regenerates the
  digest), or it accrues automatically when `/handoff-session` promotes its "Decisions".
- After editing any `##` section by hand, regenerate the digest: `npm run memory-digest`
  (or `node scripts/memory-digest.mjs`). It also warns when the digest >30 lines or any
  section >60 lines — the mechanical budget (V2-102).
- **Curation rule — keep sections bounded (≤60 lines each).** When an entry becomes a
  stable rule, promote it into CLAUDE.md / a rule file / an ADR and delete it here. Prune
  entries that no longer apply. If a section is consistently over budget, the fix is
  promotion + pruning, not a bigger budget.
- One fact per line: `YYYY-MM-DD — <fact>` (add `(ADR-NNN)` / `file:line` when
  there is a canonical home).
- **Never write secrets, passwords, tokens, or Restricted values here.** This
  file is tracked, lands on `main`, is inherited by forks, and its digest is printed into
  every session at startup — treat it like CLAUDE.md, not like `.env`.

## Gotchas — git & landing to main

- 2026-08-22 — **An UNQUOTED heredoc executes backticks in a commit message.** `git commit -F - <<MSG`
  (unquoted, so `$TRAILER` expands) also runs any `` `backticked` `` text in the prose as a command and
  substitutes the output — silently gutting sentences ("I put above ,"). Then you cannot fix it:
  `git push --force`/`--force-with-lease` is DENIED by `dangerous-commands.mjs`, so an already-pushed
  message is permanent. Fix: build the message in a file (python/`printf`) and `git commit -F <file>`,
  or quote the delimiter (`<<'MSG'`) and interpolate nothing. Recovering from a local amend you cannot
  push: `git reset --soft origin/<branch>` restores parity without discarding the tree (`git reset
--hard` and `git checkout --` are deny-listed).

- 2026-07-11 — **Landing a working-branch commit on `main` when a generator-docs commit
  (REPO-MAP/SESSION-HANDOFF regen) sits between `main` and it: use cherry-pick, NOT
  `git push origin HEAD:main`.** A plain FF would drag the generator-docs commit onto main,
  and SESSION-HANDOFF.md must stay OFF main. Pattern: `git fetch origin main` →
  `git checkout -b tmp origin/main` → `git cherry-pick <sha>` → `git push origin HEAD:main`
  → `git checkout <branch>`. Note **`git branch -d/-D` is DENY-listed** (destructive-git),
  so the temp branch can't be cleaned in-session — harmless local cruft in an ephemeral box.
- 2026-07-11 — **Landing to main is a clean FF push:** `git push origin HEAD:main` when the branch is
  main + linear commits (WS-6/7/8 all landed this way). The pre-push /ship gate runs on the push.
- 2026-07-03 (session 14) — **Can't delete remote branches from a web session** (re-verified
  2026-07-13). The local git
  bridge returns HTTP 403 on ref-deletion (`git push origin --delete`), and the GitHub MCP exposes
  no delete-branch tool. Branch pruning must be handed to the operator (commands, or the GitHub
  Branches UI). `git branch -d/-D` and force-push are also deny-listed locally.
- 2026-07-03 (session 14) — **Dependabot PRs can sit on ABANDONED history.** After a repo is rebuilt
  from a pristine template, old Dependabot branches share NO merge-base with current `main` (`git
merge-base origin/main <branch>` prints empty) — merging one resurrects a whole dead project. Check
  merge-base first; if disjoint, CLOSE the PR and hand-apply the version bump to the live files
  (resolve pinned action SHAs via `git ls-remote https://github.com/<owner>/<action> refs/tags/<tag>`).
- 2026-06-20 — Fresh containers can have local `main` far behind `origin/main`.
  Before fast-forward-merging a working branch into `main`, verify `origin/main`
  is an ancestor of the branch (`git merge-base --is-ancestor origin/main <branch>`)
  so the FF doesn't strand remote commits.

## Gotchas — stack & build

- 2026-08-27 — **Inside a `FormItem`, never pass `id` or `htmlFor` — doing so silently UNLABELS the
  control.** `components/ui/form.tsx`: `FormControl` clones its child with `{ id: formItemId }`
  (replacing yours), while `FormLabel` renders `<Label htmlFor={formItemId} {...props} />` with the
  spread LAST (so yours WINS and points at an element that no longer exists). Result: no accessible
  name — how it shipped on the ADR-070 platform-admin checkbox, the control that grants admin access.
  Typecheck, ESLint (`jsx-a11y` sees an `htmlFor` and is satisfied) and text-scraping browser probes
  all pass; only a Playwright `getByRole("checkbox", { name })` caught it. Select by ACCESSIBLE NAME
  in probes so the wiring is what's asserted. Multi-line help goes in ONE `FormDescription` (it
  registers into `aria-describedby`), not loose `<span>`s.
- 2026-08-27 — **zod STRIPS unknown keys, so REMOVING a boundary field fails silently-successfully.**
  After ADR-070 swapped `createUserSchema`'s `role: z.enum([...])` for `isPlatformAdmin`, the old
  `POST /api/users {"role":"ADMIN"}` still returned **201** — and created a VIEWER. Fails safe, but the
  caller was told "created" and got something else; a script on the old shape keeps making wrong
  accounts forever. **Remove a field → switch that schema to `z.strictObject` in the same commit**, so
  the legacy body is a 400 naming it. Found by POSTing the old payload at a running server; a schema
  diff cannot show you this.
- 2026-08-08 — **Preflight/C4 re-enable is the single highest-leverage design fix.** Tailwind
  Preflight was withheld during the AntD-coexistence slice (`app/globals.css` imported theme +
  utilities only) and was never re-enabled after AntD was removed, so native `<button>`/form-control
  chrome leaked app-wide (the "chunky raised" sidebar buttons). Fix: add
  `@import "tailwindcss/preflight.css" layer(base)` in `app/globals.css`. Safe because every
  native-element primitive (`ui/button|input|select`) already carried `appearance-none` for exactly
  this moment. A fork whose UI looks dated/heavy should confirm preflight is on first.
- 2026-07-17 — **Self-host distroless image (`Dockerfile`, ADR-035) — the build recipe, learned
  the hard way.** The image had NEVER actually been built (no daemon in prior sessions); the first
  real build+boot surfaced 5 latent defects, all masked on Vercel (where env is configured): (1) the
  builder stage needs a **build-time placeholder `AUTH_SECRET`** — `lib/env.ts` zod-parses the env at
  module load, which `next build` triggers while collecting page data (`/api/internal/audit-purge`),
  and `AUTH_SECRET` has no default; (2) a **`public/` dir must exist** (`public/.gitkeep`) or the
  runner `COPY /app/public` fails the build; (3) ship the **production-pruned full `node_modules`**
  (`npm prune --omit=dev` in the builder + `COPY node_modules`), NOT just `prisma`+`@prisma` — the
  Prisma 7 CLI's `migrate deploy` closure (`@prisma/config`→`effect`/`c12`/`jiti`) is otherwise absent
  and it crashes at boot with `Cannot find module 'effect'`; (4) **copy `prisma.config.ts`** — Prisma 7
  reads the datasource url from it (schema.prisma has no `url`), else `migrate deploy` errors
  "datasource.url required"; (5) the **smoke/boot Postgres must be pgvector** (the `vector` migration
  needs the extension). Image ~1.87 GB (the cost of in-image migration). Proven build→boot→migrate→
  serve as nonroot. (2378a91/4d8d111)
- 2026-07-11 — **React Compiler (ADR-048): on the pinned `next@16.2.9` the ONLY supported
  path is the stable Babel transform (`reactCompiler: true` + `babel-plugin-react-compiler`

## Gotchas — security, auth & hooks

- 2026-08-26 — **gitleaks flags a realistic-looking hash literal in a TEST as `generic-api-key`.**
  a `passwordHash:` fixture set to the word "argon2" plus a hyphenated word (entropy 3.61) failed
  the push gate — and this very note tripped the gate again when it quoted the literal, so don't.
  Because gitleaks
  scans HISTORY, a follow-up commit does not clear it — the commit has to be rewritten. Use a
  low-entropy English phrase for a stand-in hash, not a hash-SHAPED string.
- 2026-08-26 — **`no-prisma-unfiltered-import` is right to refuse `prismaUnfiltered` outside auth /
  recycling-bin / maintenance.** To see soft-deleted rows anyway (the unique indexes don't respect
  the filter), ask the audited client twice: the plain read, plus one naming
  `deletedAt: { not: null }` — the extension only injects `deletedAt: null` when the caller hasn't.

- 2026-08-25 — **`resolveRoot(input)` reads the SESSION cwd, so a `cd <repo> && …` inside the
  command was invisible to the four SDLC gates.** In a multi-repo session that made the qa-gate
  refuse a deploy of the PMS fork while quoting a commit from the template it was forked from —
  the gate was reading HEAD from the wrong repository. Fixed in `.claude/hooks/lib/receipt.mjs`:
  a LEADING `cd` now wins over `input.cwd`. Also worth knowing: `isDeployCommand` matches deploy
  words anywhere in the command string, so a `node -e` probe containing one gets blocked too.

- 2026-08-22 — **For gate scope, enumerate what is SAFE, not what is DANGEROUS.** An allowlist
  of gated paths missed a gate-disabling file in three consecutive breadth reviews
  (settings.json/.husky, then package.json/eslint.config, then findings-register/
  audit-allowlist/next.config/tsconfig/.npmrc). Enumerating danger is open-ended and every
  miss is a SILENT hole; enumerating safety is closed-ended and every miss is visible
  friction someone reports. Inverted to a safe-set denylist; the old allowlist was kept as
  the review-DEPTH classifier, where a miss costs a shallower review rather than none.
- 2026-08-22 — **Changing a guard's condition can convert a fail-SAFE bug into a fail-OPEN
  one.** qa-gate's `shipping` array was always empty (a malformed sha from
  `git log --format=…%x1e`, whose trailing newline glues onto every sha but the first).
  Under `shipping.length > 0 && …` that made the allow branch unreachable — it always
  denied: annoying, safe. "Fixing" the annoyance by switching to `prevQaFound && …` made
  `uncovered` always empty, so it always ALLOWED — silently shipping unreviewed code.
  Before changing a guard condition, ask what the OLD one was accidentally protecting.

- 2026-08-22 — **Fail-open governance gates mask the AUTHOR's bugs, not just runtime ones.** Four
  separate times a gate used a helper it never imported (`execFileSync`, `norm`, `isSkipAdjudicated`,
  and one more); each would have thrown `ReferenceError`, been swallowed by the fail-open handler,
  and left the gate permanently OFF while still listed as a passing check. Fail-open is correct per
  ADR-047 — it also means gate code needs stronger verification than its own runtime behaviour
  provides. Run an import audit over every hook after editing one.
- 2026-08-22 — **Two rounds of self-reviewed gate patches were not enough** (SDLC-chain wave). Round
  1 breadth review: 6 findings. Round 2, reviewing round 1's fixes: 5 more, including a live crash
  certified as "verified" in a commit message. All 11 landed in the GATE code; the skills, evals,
  descriptions, router and docs drew zero. Budget adversarial review for harness/gate work at a much
  higher rate than for product code, and treat "the author checked it" as no evidence.

- 2026-07-11 — **Security guard hooks fail-CLOSED, governance gates fail-OPEN (ADR-047).**
  `protect-secrets`+`dangerous-commands` deny on internal error; `blueprint-gate`+`build-vs-buy-gate`
  stay fail-open (a crash must not block all writes). A PERSISTENT fault in a fail-closed guard denies its

## Gotchas — subagents

- 2026-08-25 — **Distinct backup FILENAMES when mutation-testing several routes.** Backing up
  `app/api/{a,b,c}/route.ts` as `$D/$(basename $f).bak` collides on `route.ts`; the restore then
  wrote one route's body into another's file. It typechecked. Mirror the path
  (`$D/$f`) or use `git show HEAD:<path>`.

- 2026-08-22 — **A file appearing on disk during a wave does NOT mean the agent finished.**
  Wait for the completion notification, not for the path to exist. In the sdlc-chain wave the
  router's `SKILL.md` appeared, was formatted, `/ship`-ed and COMMITTED while its agent was
  still refining it; the agent's remaining edits then landed as uncommitted changes on top of
  the commit. Impact was low (prose tightening only) but it could as easily have been a
  half-written Steps section that passed format and lint. The gates check shape, not
  completeness — only the notification does. Corollary: mid-wave `git status` is not a
  progress bar.
- 2026-07-11 — **Always Glob-verify a subagent actually WROTE its output file** before
  trusting it — agents sometimes return the report as the completion _message_ instead of
  writing to disk (the v2 C13 research agent did exactly this). Re-run if the file is absent.
- 2026-07-03 — **Worktree subagents (`isolation:"worktree"`) can boot on a STALE base**
  even when the main checkout is on the tip. Fix that worked: run agents in the MAIN
  checkout scoped to DISJOINT file sets (forbid touching in-flight files); use a
  worktree only when agents truly mutate the SAME files, and verify its base
  (`git rev-parse HEAD`) first.

## Conventions discovered

- 2026-08-25 — **A sequential concurrency test is vacuous.** `Promise.all([json(await A), …])`
  awaits A _inside the array literal_, so the calls run in order and the read-time guard alone
  separates them — it passes with the conditional arbiter deleted. Start both requests, THEN
  await: `const [ra, rb] = await Promise.all([POST(a), POST(b)])`.
- 2026-08-25 — **Authority BEFORE the database read.** `withAuth` requires a session, not a
  role, so `findUnique`→404 then role-check→403 is an existence oracle for any signed-in user.
- 2026-08-25 — **A comment citing a spec clause is a claim to verify.** Two §9 gaps surfaced
  this way: a peer-pool comment named project peers the filter never read; `transfer.ts`
  promised a leaver's weights sum to <1 with nothing clamping the period. Both read as done.

- 2026-08-22 — **Mutation-test every regression test: a test that cannot fail is not a test.**
  Three tests written this session were vacuous until proven otherwise — one asserted
  fail-open on inputs that never reached the fail-open path (they lacked `..`, so review-gate
  ignored the arg and measured ambient repo state instead). The check is cheap: reintroduce
  the bug, confirm the test goes red, restore. Do it for every test guarding a defect class,
  and never write "verified" in a commit message without it.

- 2026-08-22 — **Verify by EXIT CODE, never by grepping for a success string.** `npm run evals |
grep unreadable` matched the `console.log` and hid the `ReferenceError` thrown on the very next
  line; the run exited 1 and I reported it as verified, then committed that claim. A grep for what
  you hope to see cannot detect what went wrong after it. Capture `$?`, or redirect to a file and
  read the tail.
- 2026-08-22 — **A denied Bash call skips EVERYTHING in it, not just the offending part.** A
  compound call containing a `python3` fix plus an `rm -rf` was denied for the `rm -rf`; the fix
  never ran, and later greps "confirmed" behaviour the fix was supposed to produce. After any
  denial, re-check that the edits you believed landed actually did (`grep` the file, don't assume).
  Keep destructive commands OUT of calls that also make edits.

- 2026-07-25 — **A gate that has never been exercised is not a gate — run it, do not read it.**
  In one session, FIVE gates were green while being wrong: `dangerous-commands` allowed
  `git rest0re <path>` (which discards) and `git check0ut HEAD <path>`; `scanSessionState`
  reported "land this" for any branch that merely never had the files, and skipped entirely on a
  non-`main` default branch; db-structure (c) had never once run; and `no-bare-api-route` missed
  SIX live export forms including `export { GET }`. Three were in code written hours earlier by
  the same session that declared them done. Every one was found by EXECUTING the thing —
  throwaway git repos, a real shadow DB, RuleTester over each export shape — and none by reading
  it. **When you add or narrow a gate, probe BOTH directions in the same sitting**: fixing false
  positives without checking false negatives leaves it half-built and feels finished.
- 2026-07-25 — **`docs/SESSION-HANDOFF.md` is gitignored, so a session handoff written there dies
  with the container.** Durable close-out belongs HERE (tracked, reaches `main` and forks). Write
  the handoff for the human inline; write the lesson to agent-memory.

- 2026-07-03 — **Session status is DATA, not prose.** `docs/session-state.json` is the
  single source; `SESSION-HANDOFF.md`'s two tables are RENDERED from it between
  `<!-- BEGIN/END:auto-status -->` markers via `scripts/render-handoff.mjs` (`--check`
  fails on drift, wired into `/ship` as a WARN). Edit the JSON, not the tables. The
  SessionEnd `auto-handoff.mjs` hook re-renders automatically; SessionStart surfaces it
  first. Never hand-edit inside the markers. (session-automation,
  blueprint `docs/blueprints/session-automation-auto-handoff.md`.)
- 2026-07-03 — **`/ship` green-for-HEAD signal is the gitignored `.claude/state/last-green-sha`**

  reads the gitignored file and FAILS CLOSED. Auto-spawn ships DISABLED
  (`autoSpawn.enabled=false`) and has no autonomous consumer yet — don't enable expecting
  zero-touch spawning.

## Operator directive: DESIGN BEFORE EXECUTION (binding)

2026-07-11 — Operator's self-diagnosed top-2 failure modes when building apps with this harness, to actively counter EVERY time:

1. **Poor architecture of functions/workflow + no design before execution.** The recurring failure
   is jumping to code without first architecting the functions and the workflow. COUNTER: always run
   the design/architecture pass FIRST — `/blueprint` (architecture sketch: entities/routes/services +
   where state lives + data/control flow) and `EnterPlanMode` for anything multi-file, BEFORE writing
   code. Do not "go without thinking." This is the operator's #1 ask.
2. **Poor frontend implementation.** Frontend quality is a repeat weak spot. COUNTER: use
   `/design-system` proactively (declare the design read, build from `docs/design-recipes.md` vetted
   patterns on the shipped `components/shared/*` primitives), and gate with `/design-qa` — don't
   improvise UI and fix at QA. Consider the frontend-design tooling in PHASE-2-BACKLOG §A.6.

Standing rule: think/architect/design first, implement second — for every app-building task.
