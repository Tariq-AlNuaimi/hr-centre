# CLAUDE.md — Fullstack Next.js Template (Prototype Rail)

Reusable starter for Rihal internal-tool prototypes. Next.js 16 + Prisma 7 (Postgres) + Auth.js v5 + Ant Design 6 + next-intl (`en`/`ar`, RTL) + recharts + dnd-kit + zod. Vercel + Neon; deploy = `git push`. Owner: Tariq Al-Naaimi. Audience: non-developer stakeholders reviewing via shared URLs; the operator iterates with Claude, then `/handoff` gives production to the IT team (ADR-006).

Fork lifecycle: `/rebrand` → `/first-fork` (or `/new-project` / `/deploy`) → `/quickstart` per idea → `/scale-up` per growth axis → `/handoff` at the end.

## Token thrift (binding; full policy: `docs/token-policy.md`, ADR-019)

- Delegate repo-wide searches/investigations to the **scout** agent (haiku, read-only); don't read >5 files inline for orientation. `docs/REPO-MAP.md` answers "where is X" for free.
- Output style: concise; targeted edits over rewrites; no preamble/recap fluff; read a file once unless it changed.
- When compacting, always preserve: the modified-file list, last `/ship` status, open findings, and the operator's goal.
- When the context watchdog warns, run `/handoff-session` at the next milestone; repetitive N-file jobs go through `/batch`, not one long session.
- Durable cross-session knowledge (decisions/gotchas/conventions) lives in `docs/agent-memory.md` (surfaced at SessionStart, bounded ~150 lines) — add via `/remember`; route work by model tier (haiku/sonnet/opus) per the table in `docs/token-policy.md` (ADR-022).

## Harness (`.claude/`)

Most used: `/quickstart`, `/scaffold-entity`, `/ship`, `/deploy`, `/qa`, `/conform`, `/handoff`. ## Standing instructions (binding)

- **`main` is the fork source-of-truth.** Forks are generated from `main` only. Before a session ends, land completed green work on `main`; merge often. Never land red — `/ship` green is the bar.
- **Pushed-or-it-didn't-happen (cross-session durability; #3/#14).** The remote-execution container is ephemeral and the next session clones **only what was pushed** — committed-but-unpushed commits and uncommitted changes are gone. So: commit completed work and **push it before the session ends**, and _verify the push landed_ (`git rev-list --count @{u}..HEAD` → `0`), never assume. The `Stop` hook (`.claude/hooks/session-stop.mjs`) surfaces unpushed/uncommitted state every time it changes; `/handoff-session` and `/remember` carry durable state but only if their push succeeds. If a past session "built X / seeded data" but this one can't find it, the cause is almost always an unpushed commit — say so and recover (re-derive or ask), don't claim "no access." Memory lifecycle: in-flight state → `docs/SESSION-HANDOFF.md` (committed to the branch, never merged to `main`); durable decisions/gotchas → `docs/agent-memory.md` (committed, reaches `main`, inherited by forks, surfaced at SessionStart).
- **Run `/ship` before every push** (`npm run ship` — parallel + cached, ~45s warm; stops on first failure). It is the active gate; CI workflows are dormant on the free plan and activate at the FIRST of: (a) `/handoff` to a team with Actions, (b) Actions billing unblocking, (c) a second regular contributor. Dependency cadence: ADR-017 (in-range continuously; majors via quarterly stack-refresh ADR).
- **Before any push touching auth, schemas, API routes, or `lib/`**, run the native `/code-review` and resolve findings — the fast, pre-push, diff-scoped gate (blocking).
- **After every push of code, the `senior-code-reviewer` runs** — the async, post-push breadth pass that owns what the diff gate can't see (cross-cutting invariant completeness, adversarial/output-side trust boundaries, operational/time-varying drift, architecture). It layers on top of `/code-review`, never replaces it. Preferred path is CI (`.github/workflows/senior-review.yml`; non-blocking; dormant until `ANTHROPIC_API_KEY` + triggers are set); when CI is off, invoke the `senior-code-reviewer` agent on the change before calling the work done. Portable to any repo/stack via `node scripts/install-senior-review.mjs` (ADR-020; `tools/senior-review/README.md`).
- **After a green `/ship`, if the fork has no Vercel project, offer `/deploy`** (ADR-009; needs `NEON_API_KEY` + `VERCEL_TOKEN` + egress to `api.vercel.com`/`console.neon.tech` — see `.claude/skills/deploy/SKILL.md` for the full env table). If preflight reports blocked egress, surface the hosts; don't mistake it for a missing token.
- **A live URL is the default; verify access by RUNNING, not by assuming.** The operator wants a shared `*.vercel.app`/custom-domain URL, not a local-only setup. Never tell the operator "I don't have access" / "tokens aren't set" / pivot to `npm run dev` _before_ the relevant provisioner preflight has actually run and failed — the preflight (`scripts/deploy.mjs`/`new-project.mjs`) is the only authority, printing `Egress OK.` or the exact blocked hosts, and the env-check names any missing token. When it fails, report the _specific_ cause (blocked egress — not token-fixable — vs. a named missing token). Local dev is the fallback only when the operator asks for it or egress is genuinely blocked with no egress-capable machine available.
- **Market benchmark before building.** Any brainstorm/requirements pass starts with a web search of existing products/libraries/starters, summarized with trade-offs before designing. Specs include a short "market scan" section.
- For real multi-file features use Superpowers (plugin: brainstorm → spec → plan → TDD); for disposable idea-to-URL use `/quickstart`. Don't spend spec ceremony on throwaways.
- **Blueprint before building (the pre-build gate).** Run `/blueprint` before building a feature: the **lightweight track** (one clarifying-question round + a one-line design + architecture read) for disposable `/quickstart` work, the **full track** (committed `docs/blueprints/<feature>.md`: user stories + happy/worst scenarios + architecture sketch + tier + open questions resolved via `AskUserQuestion`) for real multi-file work or anything on the Ask-before surface. The blueprint is the contract `/qa`/`/uat`/`/manual-uat` trace coverage against; building without it — assuming requirements, then filling gaps with guesses — is the failure this gate prevents. Don't silently drift from a signed-off blueprint; update it and re-confirm.
- **Auto-plan high blast-radius / ambiguous work.** Before acting, self-assess and call `EnterPlanMode` (plan first, await sign-off) when ANY holds: the change is multi-file or multi-step; it touches the Ask-before surface (auth, `lib/`, Prisma schema/migrations, API routes, `middleware.ts`, `eslint-rules`); requirements are ambiguous/underspecified; the code is unfamiliar; or the change is hard to reverse. Pair plan mode with `/blueprint` (the blueprint is the requirements half of the plan). Act directly (no plan) for questions/read-only lookups, single-file low-risk edits, typos/renames, and disposable `/quickstart` work. On a close call, plan — and name the trigger in one line.

## Five Pillars (binding — gates, not vibes)

Every change is judged against five pillars (defined in full in `docs/uat-rubric.md`). These are **gates**, not after-the-fact rubric anchors — `/ship` and `/qa` enforce them and a violation blocks, the same way a security violation does.

1. **Speed** — RSC reads, no needless round-trips, debounced inputs, bounded payloads.
2. **Secure** — auth wrappers + zod on every route; Restricted data gated; audit on; no secret/PII leakage. (Hardest-gated: the eleven ESLint rules + the Hard rules below.)
3. **Maintainable** — reuses existing primitives/services (check `docs/REPO-MAP.md` before writing new); typed; no dead code; small, forward-compatible migrations.
4. **Scalable** — handles growth: list/read routes paginate or bound their result set; no N+1; bulk paths not N×1; rate-limit-aware.
5. **High-Quality** — correctness + UX fidelity; honest empty/loading/error states (no green toast over a failure); axe-clean; no deprecation drift.
   `/ship` runs the automatable pillar checks (security via ESLint; scalability via the unbounded-query check) **and hard-fails on any `status: open` wave-off in `docs/findings-register.md`** — an un-adjudicated pillar concern blocks green, the same as a failing test. The non-automatable pillars are a **blocking checklist** `/ship`/`/qa` must affirm, not skip. A pillar concern you choose not to fix is a **wave-off**: log it in the register and the operator adjudicates it (accepts/schedules) before `/ship` can go green — it is never silently dropped.

**Conditional 6th pillar — AI-Quality (ADR-042).** Forks that ship AI endpoints add a sixth pillar: **AI-Quality** (defined in `docs/uat-rubric.md`). It governs AI routes only and is **INERT** on any fork with no `lib/ai` usage / no `AI_API_KEY` — no findings, no `/ship` effect. It is a gate like the five above: an automatable slice (the `/ai-eval` gate, ADR-036 — dormant until `AI_API_KEY` + fixtures land — plus the eleven ESLint rules — `no-direct-anthropic-sdk` forces model access through `@/lib/ai` (never `new Anthropic`), and `no-secret-env-in-console` blocks secret/PII logging) and a blocking checklist `/qa`/`/uat` affirm on every AI surface (eval pass-rate, prompt-injection resistance at the boundary, honest AI failure states — 503 when unconfigured, no hallucinated success — RAG grounding/citation, bounded cost/tokens, and no Restricted/PII in prompts or logs). An unfixed AI-Quality concern is a wave-off in `docs/findings-register.md`, adjudicated like any other pillar. Adds no new `/ship` phase — enforcement is the existing (dormant) `/ai-eval` gate + ESLint rules, so a non-AI fork's green is untouched.

## Hard rules

- **The Five Pillars are gates, not vibes.** Every change must satisfy Speed/Secure/Maintainable/Scalable/High-Quality (above). The automatable slice is enforced by `/ship` (ESLint security rules + the unbounded-query scalability scan); a concern you don't fix is a **wave-off logged in `docs/findings-register.md`**, and `/ship` stays RED until it's adjudicated. Never silently drop a pillar concern.
- **Build-vs-buy is a hard gate, not advice (ADR-032).** Before hand-building a new capability under `lib/`, do the reuse scan — check `docs/REPO-MAP.md` + `lib/` + `components/shared/` for an existing primitive, the `/scale-up` recipe table, then web-search for a library/open-source fit — and record the decision in `docs/build-vs-buy-ledger.md` (a `Scope:`-glob entry naming what you considered and why build-vs-adopt). The `build-vs-buy-gate.mjs` PreToolUse hook **denies** the new file until that entry exists. This is the enforcement half of "Market benchmark before building" + the Maintainable pillar's "reuse existing primitives"; recording the entry is not a bypass, it _is_ the scan.
- **Blueprint before feature code is a hard gate, not advice (ADR-033).** A new API route (`app/api/**/route.ts`) or page (`app/**/page.tsx`) requires a `docs/blueprints/<feature>.md` whose `Scope:` glob covers it — the `blueprint-gate.mjs` PreToolUse hook **denies** the new file until one exists. Run `/blueprint` first (user stories + happy/worst scenarios + open questions resolved via `AskUserQuestion`); both tracks write a `Scope:`-bearing file (full doc, or a minimal stub for `/quickstart`). The blueprint is the contract `/qa` and `/uat` trace against; building without it is the guess-then-rebuild this gate prevents.
- **Over-engineering is a hard gate, not advice (ADR-034).** `/ship`'s `complexity` check (phase A) flags any NEW product file in the diff that blows the budget (>350 code lines or >40 branch tokens — a cyclomatic proxy) and goes **RED** unless waived via `complexityAck` in `project.config.json` + an adjudicated `docs/findings-register.md` line. Split, simplify, or reuse a primitive before adding a sprawling file. This is the automatable slice of the Maintainable + High-Quality pillars; it completes the enforcement trio (build-vs-buy → blueprint → complexity), all on one pattern: a gate + a committed adjudication artifact.
- **Push completed work before the session ends.** A fresh container clones only what is pushed, so committed-but-unpushed commits are silent data loss. The `Stop` hook (`.claude/hooks/session-stop.mjs`) **hard-blocks** the turn from ending while commits are unpushed (uncommitted WIP is a warning, not a block); `/handoff-session` and `/remember` verify their pushes.
- **Never commit `.env`.** Auth/DB/SMTP credentials are Restricted (SECURITY.md §1). gitleaks gates every push via `/ship`.
- **Never log** any Restricted env var. ESLint `no-secret-env-in-console` catches the obvious form; judgement covers the rest. Email bodies may carry Restricted content — `lib/email.ts` logs metadata only; never log `opts.text`/`opts.html`.
- **Adding a Restricted column?** Extend `SCRUB_FIELDS` in `lib/prisma/audit-extension.ts` AND its assertion in `tests/contracts/audit-scrub.test.ts` in the same commit. Excel exports are a separate gate — audit column lists per route.
- **Go through Prisma.** No raw SQL except `prisma.$queryRaw`/`$executeRaw` with parameter placeholders; never `$executeRawUnsafe` on user input; no `SELECT *`; no raw UPDATE/DELETE without WHERE.
- **UI → API route → service → Prisma.** Only server components and API routes touch `prisma` (`no-prisma-in-client` rule).
- **Use the auth wrappers** (`lib/api-helpers.ts`) on every route: `withAuth` / `withAdminAuth` / `withEditorAuth` (ADMIN|EDITOR) / `withInternalAuth` (shared-secret for schedulers; Vercel-Cron routes opt into `{ bearer: true, skipWhenUnconfigured: true }` — ADR-018) / `withApiAuth` (Bearer for machine consumers, the `/api/v1` seam — ADR-013). Compose `withRateLimit` OUTSIDE the auth wrapper.
- **Audit is automatic but fragile.** `auditExtension` covers every create/update/delete outside the EXCLUDE set; don't extend EXCLUDE without an ADR. Soft-delete is opt-in (`/scaffold-entity` wires it; manual additions must too). `prismaUnfiltered` ≠ `prisma` — auth + recycling-bin only.
- **Validate at the API boundary with zod** (`lib/validations/`). **Never cast `session` to `any`** (`no-any-cast-on-session` rule; `types/index.ts` types `session.user.role`).
- **Naming:** snake_case tables (`@@map`); camelCase Prisma fields/TS; PascalCase React + models + enums.
- Local ESLint plugin (`eslint-rules/`, all at `error`): `no-prisma-in-client`, `no-any-cast-on-session`, `no-secret-env-in-console`, `no-bare-internal-route`, `no-raw-hex-color` (tokens come from `app/tokens.css` / `brand.config.ts` / `chart-palette.ts`; ADR-015), `no-unaudited-bulk-write` (Prisma bulk/upsert on an audited model bypasses the audit log; ADR-010), `no-raw-sql-unsafe` (`$queryRawUnsafe`/`$executeRawUnsafe` are unparameterized SQL-injection vectors; OWASP A03), `no-rate-limit-inside-auth` (`withRateLimit` must compose OUTSIDE the auth wrapper so floods are throttled before auth work runs; OWASP A04), `no-restricted-export-column` (a secret-named field as a `toExcel` column key leaks the raw value into the downloadable `.xlsx`; `SCRUB_FIELDS` does not cover exports; SECURITY.md §1), `no-prisma-unfiltered-import` (`prismaUnfiltered` bypasses soft-delete + audit, so it's allowlisted to auth/recycling-bin/maintenance files — an ordinary route importing it is an Ask-before change), `no-direct-anthropic-sdk` (`@anthropic-ai/sdk` may only be imported inside `lib/ai/**`; model access everywhere else goes through the `@/lib/ai` barrel so the `isAiConfigured()` gate, endpoint-agnostic client, default model/max_tokens, and GenAI tracing can't be bypassed — the AI-Quality pillar's automatable slice, ADR-042). Justified suppressions: single-line disable; if security-related, log in SECURITY.md §12.

## UI Definition of Done (full rubric: `docs/uat-rubric.md`)

**Build it right the first time with `/design-system`** (proactive: declare the design read, build from `docs/design-recipes.md`'s vetted patterns on the shipped `components/shared/*` primitives) — don't improvise UI and fix it at QA. Declare the design read first (surface/audience/tone/density); one accent, one primary action per screen, no nested Cards, no emoji-as-icons. Real empty/loading/error states; on-token spacing/colors/type; zod-backed validation messages at the boundary; no dead controls; honest feedback (no green toast over a failure); responsive + RTL (`ar`) + dark hold; axe clean of serious/critical. QA runs in gated tiers: `/design-qa` → `/ship` + risk-based cases → `/uat`, orchestrated by `/qa`; a red gate stops the line. The operator signs off UAT.

## Project tiers

`project.config.json` `"tier": "personal" | "shared"` (default personal). Tier scales ceremony, never the security floor: auth wrappers on every route, no leaked secrets, zod at every boundary, no raw SQL, the eleven ESLint rules at `error`, audit log ON, `/ship` before every push. `shared` adds: `/handoff` package, SECURITY.md §9 compliance, CI activation at handoff, formal findings register. `personal` skips those (audit log stays ON). **`/ship` enforces tier-vs-reality:** if the repo has ≥2 distinct human contributors (the same line that activates CI) while tier is still the `personal` default, `/ship` fails — a multi-contributor tool is shared and shouldn't skip the shared-tier ceremony. Fix by setting `"tier": "shared"`, or, if it's genuinely still personal, record that with `"tierAck": "personal"` in `project.config.json`.

## Ask before

- Installing a runtime dep > 50 KB minified (needs ADR or `/scale-up` recipe)
- Touching `lib/auth.ts`, `lib/rate-limit.ts`, `lib/email.ts`, `lib/export.ts`, `lib/api-helpers.ts`, `middleware.ts`, anything under `lib/prisma/`, `eslint-rules/`, or `prisma/migrations/`
- Adding a model to the audit EXCLUDE set; adding a public path or `/api/internal/*` route; bypassing any auth wrapper; changing the `Role` enum or role checks
- Disabling any `rihal-template/*` rule beyond a single-line disable; suppressing a Semgrep/gitleaks/npm-audit finding (log in SECURITY.md §12)
- Pushing to `main` directly when branch protection is on; changing the ADR-001 locked stack (write a superseding ADR first)

## Known traps (don't "fix")

- The context-watchdog fires per **session depth** (60/80/90% of the token window), not per repo — there is no template-vs-fork gate in `.claude/hooks/context-watchdog.mjs`. A short fork session simply hasn't crossed a threshold yet. If a fork's watchdog is genuinely silent, the cause is missing wiring: `.claude/settings.json` (which binds the hook to `UserPromptSubmit`) is a `/sync-from-template` REVIEW layer, so a fork that pulled the hook script but skipped the settings diff has the script with no event binding. Reconcile `settings.json`, don't rewrite the hook.
- Generated Prisma client lives in `generated/prisma`; imports go through that path.
- Auth.js uses JWT sessions; the `sessions` table is only for OAuth account linking. `middleware.ts` runs on the Node runtime.
- Locales are config-driven (`project.config.json` `locales`/`defaultLocale` → `i18n/config.ts`): add/remove a locale there and the routing, the `<html dir>` direction (`localeDirection`/`directionForLocale`), the shared locale-prefix regex (`localePrefixRegex`, imported by middleware + chrome), and the switcher visibility all follow — no hand-edited `(en|ar)` regex anymore. RTL is automatic for `ar`/`he`/`fa`/`ur`. Default ships English-only; `messages/ar.json` + RTL code stay inert until a fork sets `"locales": ["en","ar"]`.
- Rate limiter is in-memory per-instance — fine until multi-instance; then Upstash via `/scale-up`.
- `sendEmail` returns `{ sent: false }` when `SMTP_HOST` unset — it does NOT throw.
- CSP allows `'unsafe-inline'` script+style (AntD SSR + Next bootstrap). Vercel auto-injects `AUTH_URL`; don't set it manually unless wiring a custom domain first.
- `vercel.json` runs `prisma migrate deploy` every build — keep migrations small and forward-compatible; never drop columns the running version still reads. It also ships the daily audit-purge cron (ADR-018; silent no-op until `CRON_SECRET` is set).
- File uploads are not wired (ADR-006); PDF export is intentionally absent from `lib/export.ts` (pdfkit fragile in serverless).
- Docker is a **standard, mandatory build artifact** (ADR-030, supersedes ADR-023's opt-in stance): the image build is a gate at `/ship --full`, `/deploy`, `/handoff`, and CI (the fast `/ship` loop stays image-free). The `DOCKER_BUILD=1` gate in `next.config.ts` is **unchanged** — `output: "standalone"` is still emitted only under that env, so the Vercel build is byte-for-byte untouched; don't re-enable standalone unconditionally (it does nothing for Vercel). Vercel + Neon stays the default **deploy** path (ADR-006). Escape hatch for an env that genuinely can't build images: `"dockerAck"` in `project.config.json` + an adjudicated ADR-030 line in `docs/findings-register.md`. Use `make docker-build` / `make docker-up`.
- The root `app/not-found.tsx` is deliberately context-free (no providers): Next 16 prerenders `/_not-found` outside `[locale]`. If a fork's build dies in `/_global-error` or `/_not-found` with a `useContext` TypeError, that's upstream Next regression #85668/#86178 — fix with a context-free root file, never by editing the locale providers. Pinned next@16.2.9 builds clean.
- After large route deletions, a stale `.next` can break typecheck with TS2307 into `.next/types` — `npm run ship` auto-heals this.

When in doubt, stop and ask.
